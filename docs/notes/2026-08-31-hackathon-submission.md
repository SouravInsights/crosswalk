# Hackathon submission: WebMCP Challenge

**Date:** 2026-08-31. Deadline: **Sep 3, 1:00pm PDT**. Rules: https://webmcp.devpost.com/rules

## What we submit

The project is **webmcp-codegen, proven by a live app**. The rules require a WebMCP-powered web app at a working live URL, openable in ChatGPT's in-app browser (WebMCP on by default) or Chrome 149+ with `#enable-webmcp-testing`. A CLI alone does not qualify. So the submission is:

- **The live URL**: an app whose WebMCP tools were generated by codegen, not hand-written. This is what judges experience.
- **The repo**: the code story. Judges may screen it with automated analysis; the README leads with the product.

The analytics and audit work is post-hackathon. It does not fit the challenge frame and we do not bend it to fit.

## Submission checklist

- [ ] Live URL, working in ChatGPT's in-app browser (test this first, it is the default judging environment)
- [ ] If the app needs auth: demo account credentials go on the submission form
- [ ] Public repo with the license detectable in the About section (LICENSE is on main; flip the repo public)
- [ ] Text description answering: why this use case fits WebMCP; how it makes UX better; what people and agents can do together that was difficult or impossible before; how WebMCP was implemented (this is where codegen's story goes)
- [ ] YouTube video under 3 minutes, with audio narration covering what we built and how we used WebMCP; no third-party trademarks, no copyrighted music
- [ ] Submit before Sep 3, 1:00pm PDT

## Judging criteria, mapped

1. **WebMCP leverage** (thorough, skillful, non-trivial): 73 tools generated from a real production OpenAPI spec, safety classification on every tool, the audit pass, human-in-the-loop on mutations.
2. **Real problem, real audience**: depends on the app vehicle below.
3. **Creativity / novelty**: an existing app turned agent-native by generated tools, with an audit that catches what naive generation would expose (payment webhooks, admin endpoints). Nobody else in the ecosystem tells the safety story.
